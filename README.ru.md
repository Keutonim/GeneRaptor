# GeneRaptor

**Локальная студия для генерации статей с помощью ИИ.** Одна команда запускает
приложение и сама открывает его в браузере — вводить токен не нужно, — а один
файл SQLite хранит всё.

GeneRaptor превращает тему в исследованную, структурированную статью с
проверенными фактами и обложкой — локально, на вашей машине, без облачного
аккаунта.

Продукт отрасле-нейтрален: те же одиннадцать ролей пишут для любого бизнеса и
любой темы, а постоянный гейт не даёт отраслевым формулировкам попасть в
поставляемый код.

---

## Требования

- **Node.js 20 или новее** (нужен и CLI, и сборке)
- API-ключ LLM-провайдера (по умолчанию RouterAI; подойдут OpenRouter, Ollama
  или любой OpenAI-совместимый endpoint). Ключ можно добавить позже в интерфейсе —
  см. **Как настроить ключи**.

## Установка и запуск

```bash
npx generaptor
```

Команда запускает локальный сервер, печатает в терминал URL и
**одноразовый токен** и сама открывает приложение в браузере по умолчанию:

```
  GeneRaptor is running!
     UI:          http://127.0.0.1:5173 (Vite dev server)
     API health:  http://127.0.0.1:8787/api/health
     WS:          ws://127.0.0.1:8787/ws
     Data dir:    C:\Users\you\.generaptor
[Auth] ----------------------------------------------------------
[Auth] token: <одноразовый токен, 43 символа>
[Auth] Paste this token at http://127.0.0.1:5173 to unlock the app.
[Auth] ONE-TIME: single use, valid for 15 min
[Auth] ----------------------------------------------------------
[Auth] Opening the app in your default browser…
```

**Токен вводить не нужно.** Браузер открывается с токеном во фрагменте адреса,
приложение само обменивает его на сессионную cookie и убирает токен из адреса —
вы сразу попадаете в студию. Токен остаётся одноразовым и действует 15 минут;
копия в терминале — только запасной путь.

**Закрыли вкладку?** Сессионная cookie принадлежит браузеру, а не вкладке:
нажмите в старой вкладке **Обновить** — приложение проверит статус сессии и
откроет студию. Если вкладку закрыли до обмена, запустите студию заново: она
откроет новую вкладку с новым токеном. Ручной путь тоже всегда доступен —
откройте напечатанный URL и воспользуйтесь ссылкой «Ввести токен вручную» на
экране-подсказке.

Хотите открывать браузер сами? Запустите с `--no-browser`, откройте
напечатанный URL и воспользуйтесь той же ссылкой «Ввести токен вручную».

Если хотите короткую команду, установите пакет глобально:

```bash
npm install -g generaptor
generaptor
```

Из клона репозитория:

```bash
npm ci
npm run build
npm start
```

### Опции CLI

| Опция | Назначение |
| --- | --- |
| `--port <n>` | Порт локального сервера (`5173` в dev-режиме, `8787` в собранном виде) |
| `--data-dir <path>` | Каталог с базой SQLite (по умолчанию `~/.generaptor`) |
| `--no-auth` | Отключить вход по токену — приложение стартует без токена и печатает громкое предупреждение (браузер при этом всё равно открывается, просто без токена) |
| `--token <value>` | Использовать фиксированный многоразовый токен вместо одноразового — браузер тогда **не** открывается автоматически: многоразовый токен не должен попадать в адресную строку |
| `--token-ttl <value>` | Время жизни сессионной cookie: `session` (до закрытия браузера), `24h` (по умолчанию), `7d`, `30d` |
| `--host <address>` | Интерфейс, на котором слушает API (по умолчанию `127.0.0.1`, только localhost) — адрес обязателен, а не-loopback-привязка печатает предупреждение о сетевой доступности |
| `--no-browser` | Не открывать браузер автоматически — напечатать URL и токен, вход через ручной ввод |
| `--help`, `-h` | Показать справку и выйти |
| `--version`, `-v` | Показать версию и выйти |

## Первая генерация

1. Приложение само откроется в браузере — вводить токен не нужно.
2. Перейдите в **Настройки → Провайдеры**, выберите провайдера, введите API-ключ
   и сохраните.
3. В **Настройки → Модели** выберите модель для каждого уровня.
4. Откройте вкладку **Генерация**, введите тему и запустите прогон.

Под темой есть необязательное поле **«Уточнения к теме»** со счётчиком
`{n}/1000` (максимум 1000 символов). Указания попадают в промпт автора и
подготовителя задания как приоритетные для акцентов и подачи — они не отменяют
факты, профессиональную корректность и SEO-ядро. Пустое поле не сохраняется;
после успешного запуска поле очищается.

Конвейер планирует структуру, исследует тему, пишет статью, проверяет факты и
готовит обложку. Прогресс приходит в реальном времени через WebSocket.

## Три вкладки

| Вкладка | Что делает |
| --- | --- |
| **Генерация** | Тема, уточнения к теме, запуск агентного конвейера, доработка результата, генерация и правка обложки |
| **История** | Готовые статьи, полный отчёт о прогоне, копирование и скачивание текста и обложки, удаление статьи |
| **Настройки** | Провайдеры и ключи, модели по уровням, генерация обложек, роли агентов, язык и тема |

## Провайдеры и модели

Поддерживаются четыре вида провайдеров: **RouterAI**, **OpenRouter**, **Ollama**
(локальные модели) и **custom** (любой OpenAI-совместимый base URL). Провайдеры
и ключи хранятся в локальной базе — API-ключ никогда не возвращается в браузер.

Сохранённые ключи шифруются на покое (AES-256-GCM). Ключ шифрования лежит в
отдельном файле рядом с базой (`provider-secrets.key`, права `0600` на POSIX),
поэтому копии одной базы недостаточно, чтобы раскрыть ключи.

RouterAI и OpenRouter игнорируют сохранённый адрес и используют свой
стандартный endpoint; оператор может указать RouterAI другой адрес через
переменную окружения. Адрес **custom** проверяется перед использованием:
только `http`/`https`, без учётных данных внутри URL и без приватных,
loopback, link-local, CGNAT- и cloud-metadata-адресов — если не задана
`GENERAPTOR_ALLOW_PRIVATE_NETWORK=true` (Ollama может использовать loopback).
Каждый ключ привязан к одному адресу: ключ из окружения уходит только на
стандартный или заданный оператором адрес, а сохранённый — только на адрес
своего провайдера (стандартный для RouterAI и OpenRouter, сохранённый — для
custom).

**Адрес провайдера (endpoint).** Поле base URL редактируется в **Настройки →
Провайдеры** только у **custom** и **Ollama**: у RouterAI и OpenRouter адрес
фиксированный (задётся окружением, поле показывает подсказку). У **custom**
адрес обязателен — без него сохранение отклоняется. Адрес проверяется сервером
до записи: схема `http`/`https`, без логина/пароля внутри URL, без приватных и
loopback-адресов (кроме Ollama). Отказ сервера показывается **у поля**
стандартным текстом причины (например, «Адрес внутренней сети запрещён
политикой»), а не общим «Bad Request»; клиент понимает оба формата серверной
ошибки — плоский и вложенный.

Модели назначаются по уровням, чтобы дорогая модель работала только на важных
шагах:

| Уровень | Для чего |
| --- | --- |
| `critical` | Планирование, фактчекинг и контроль качества |
| `generation` | Написание и переписывание статьи |
| `standard` | Исследование и вспомогательные шаги |
| `cover` | Генерация изображения обложки — строка только для чтения: модель управляется в разделе «Генерация обложек» |

## Веб-поиск

Шаг исследования использует один подключаемый слой веб-поиска с несколькими
бэкендами. **Serper.dev — основной движок** (бесплатный ключ, карта не нужна);
**фоллбек — Tavily free** (бесплатный ключ, 1000 кредитов/мес). Без ключей работает
бесплатная резервная цепочка: Tavily без ключа → Википедия → Викиданные, а пустой
результат — допустимый ответ, а не ошибка. Цепочка деградирует честно: бесключевой
Tavily с части хостов отдаёт 403, и цепочка переходит к Википедии, а не падает.

| Бэкенд | Ключ | Примечание |
| --- | --- | --- |
| Serper.dev | `GENERAPTOR_SERPER_API_KEY` | основной движок — бесплатный ключ, карта не нужна (стартовый пакет 2500 запросов); фактическая ёмкость выдачи — **10 результатов**, пагинация не поддерживается |
| Tavily | `GENERAPTOR_TAVILY_API_KEY` | фоллбек по ключу (1000 кредитов/мес) |
| Tavily (без ключа) | — | тот же endpoint в анонимном режиме; часть хостов может отказать |
| Yandex Search API | `GENERAPTOR_YANDEX_API_KEY` | платный; используется только по явному выбору |
| Википедия / Викиданные | — | официальные, бесплатные, без ключа |
| DuckDuckGo | — | неофициальный скрейпинг, только opt-in, никогда в авто-цепочке |

Тематические вертикали — OpenAlex, Crossref, Europe PMC, GDELT, Nominatim,
OpenLibrary, Stack Exchange, Hacker News — это keyless-источники, которые
подключаются автоматически, когда тема совпадает с их тематикой; основным поисковым
движком они не выбираются и добавляют свои результаты поверх основной цепочки с
атрибуцией источника.

Бэкенд выбирается в **Настройки → Провайдеры → Поисковые источники**; выбор
сохраняется в браузере и применяется к запросам поиска. Вертикали показаны там с
пометкой «используется автоматически по теме», и блок честно подсказывает, что ключ
Serper включает основной движок, а без ключа работает бесплатная цепочка. Блок
показывает имя переменной окружения выбранного бэкенда и состояние настройки — поля
ввода поискового ключа в интерфейсе нет, поэтому поисковые ключи живут только
в окружении.

Ключ задаётся в `.env` (см. `.env.example`):

```bash
GENERAPTOR_SEARCH_BACKEND=serper   # auto | tavily | tavily-keyless | serper | yandex | wikipedia | wikidata | duckduckgo
GENERAPTOR_SEARCH_LANG=ru          # ru | en
GENERAPTOR_SERPER_API_KEY=…        # или GENERAPTOR_TAVILY_API_KEY / GENERAPTOR_YANDEX_API_KEY
```

Без ключа Serper основной движок выключен и работает бесплатная резервная цепочка
(Tavily без ключа → Википедия → Викиданные) — исследование беднее; задайте
`GENERAPTOR_SERPER_API_KEY` для полноценных результатов; Yandex остаётся платным
opt-in.

**Ключ Serper.dev:** получите бесплатный ключ на [serper.dev](https://serper.dev) —
карта не нужна — и включите его через `GENERAPTOR_SERPER_API_KEY` в `.env` (см.
`.env.example`) или в окружении перед запуском приложения. Serper.dev — основной
поисковый движок; без ключа работает бесплатная резервная цепочка (Tavily без ключа →
Википедия → Викиданные). Фактический потолок выдачи — **10 результатов** на запрос
даже при запросе большего числа, пагинации нет: итерации расширения источников
останавливаются, когда итерация не дала новых ссылок, поэтому статья тратит два
поисковых кредита (стартовый сбор + одна итерация) вместо шести.

## Как настроить ключи

**В этом репозитории нет API-ключей.** Каждый пользователь приносит свои — одним
из двух способов:

- **Переменная окружения** — положите ключ в локальный файл `.env` (за основу
  возьмите `.env.example`) или экспортируйте его в оболочке перед запуском.
  Переменные, которые читает приложение, перечислены в `.env.example`;
  `ROUTERAI_API_KEY` — для провайдера по умолчанию.
- **Настройки** — добавьте ключ в **Настройки → Провайдеры**. Он зашифрован
  на покое (AES-256-GCM) и никогда не возвращается в браузер.
- **Поисковые бэкенды** — слой веб-поиска читает ключи только из окружения
  (`GENERAPTOR_TAVILY_API_KEY`, `GENERAPTOR_SERPER_API_KEY`,
  `GENERAPTOR_YANDEX_API_KEY`); поля поискового ключа в интерфейсе нет. См.
  примечание о Serper.dev в разделе **Веб-поиск** выше.

Файл `.env` и каталог данных (по умолчанию `~/.generaptor/`, где лежат база и
файл `provider-secrets.key`) не попадают в git: держите их вне системы контроля
версий и никогда не вставляйте ключ в issue или pull request — там он станет
частью публичной истории.

## Роли агентов

Конвейер состоит из одиннадцати ролей: выбор темы, подготовка задания, работа
с базой знаний, исследование, семантическая стратегия, проектирование
структуры, авторство, фактчекинг, SEO-проверка, контроль качества и
очеловечивание. Каждую роль можно включить или выключить и назначить ей
модель по уровням в разделе **Настройки → Роли**.

## Обложка: fresh и refine

Панель обложки генерирует изображение для статьи и позволяет дорабатывать его:

- **Fresh** — сгенерировать новую обложку по текущему промпту.
- **Refine** — описать нужное изменение (до 500 символов) и перегенерировать
  поверх текущей обложки.

Настраиваются разрешение (`512`, `1K`, `2K`, `4K`), качество (`auto`, `low`,
`medium`, `high`) и формат (`png`, `jpeg`, `webp`), а также месячный бюджет в
рублях, который останавливает неконтролируемые расходы.

### Панель «Генерация обложек»

Все параметры генерации обложек живут в одном месте — **Настройки → Генерация
обложек**:

- **Модель изображения** — модель генерации (список поддерживаемых или свой id);
- **Модель сжатия статьи** — необязательное переопределение; пустое значение
  наследует модель уровня `standard` из окружения;
- **Формат** — соотношение сторон (`16:9`, `1:1`, `9:16` и другие);
- **Разрешение** — `512`, `1K`, `2K`, `4K`;
- **Качество** — `auto`, `low`, `medium`, `high`;
- **Файл** — формат выходного изображения: `png`, `jpeg`, `webp`;
- **Шаблон промпта (SYSTEM)** — промпт агента-иллюстратора (до 8000 символов,
  хранится байт-в-байт; кнопка «Сбросить к шаблону» возвращает дефолт локально,
  без записи);
- **Генерировать автоматически** — создавать обложку сразу после статьи;
- **Лимит в месяц, ₽** — бюджет, останавливающий генерацию при исчерпании.

Панель — **единственный источник правды** для модели обложки: строка уровня
`cover` в разделе «Модели» только показывает текущую модель и перечитывается
после сохранения панели. Настройки хранятся в базе SQLite (таблица
`cover_settings`); сами изображения — в каталоге `<data-dir>/covers/` (см.
**Где лежат данные**).

## Экспорт и изображения

Готовую статью можно скопировать или скачать как **HTML**, **обычный текст**
или **Markdown**. Изображение обложки скачивается отдельным файлом.

## Одноразовый токен

GeneRaptor рассчитан на запуск на вашей машине, но вход по умолчанию
включён:

- При каждом старте лаунчер генерирует **одноразовый токен**, печатает его в
  терминале ровно один раз и открывает браузер с токеном во **фрагменте** адреса
  (`#token=…`). Фрагмент не уходит на сервер, поэтому токен не попадает ни в
  логи запросов, ни в заголовок `Referer`.
- Приложение само обменивает токен на сессионную cookie — ровно одна попытка,
  без поля ввода и без перезагрузки страницы — и сразу убирает фрагмент из
  адреса и из записи истории. В браузере токен нигде не хранится: сессия живёт
  в httpOnly-cookie (`generaptor_auth`, `SameSite=Lax`, path `/`, `Secure` — только
  за TLS, время жизни 24 ч по умолчанию; `--token-ttl session` делает cookie
  браузерной, до закрытия браузера).
- Токен одноразовый и действует 15 минут. Повторный обмен отклоняется с 401;
  перезапуск выдаёт новый токен и (без явного `ACCESS_GATE_HMAC_KEY`/`JWT_SECRET`)
  обесценивает прежние cookie. Уже открытая вкладка показывает подсказку —
  нажмите в ней **Обновить**, когда новая вкладка откроет приложение.
- Если обмен не удался, приложение показывает экран-подсказку, а не поле ввода:
  устаревшая ссылка, превышение попыток (с обратным отсчётом и автоматическим
  повтором) или недоступный сервер. Вторичная ссылка **«Ввести токен вручную»**
  открывает классический экран токена — это запасной путь, не основной.
- `--no-browser` отключает автооткрытие: откройте напечатанный URL сами и
  воспользуйтесь ручной ссылкой. Автооткрытие также пропускается в CI, в
  неинтерактивном терминале (нет TTY на stdout), при `NODE_ENV=test`, при
  фиксированном `--token` и когда UI не раздаётся; сбой открытия никогда не
  роняет лаунчер — он печатает URL для ручного открытия.
- `--token <value>` задаёт многоразовый токен, `--token-ttl` — время жизни
  сессионной cookie.
  Фиксированный токен не кладётся в адрес браузера: автооткрытие пропускается,
  вход — через ручную ссылку.
- `--no-auth` выключает вход. Приложение печатает громкое предупреждение:
  тогда любой, кто достучится до порта, сможет им пользоваться. Браузер
  открывается без токена, приложение доступно сразу. `GET /api/auth/status`
  тогда отвечает `{"authenticated": true}` даже без cookie: гейт выключен —
  авторизован каждый, это публичный факт конфигурации, а не обход гейта. Клиент
  всегда ветвится по телу ответа, а не по HTTP-коду.
- Ручной экран остаётся **фоллбэком**, а не основным путём. Одноразовый токен
  доставляется во фрагменте адреса, который до сервера не доходит, а многоразовый
  `--token` не должен попадать ни в адресную строку, ни в историю браузера.
  Ручной экран нужен с `--token`, при удалённом bind и чтобы попасть внутрь без
  перезапуска студии.
- Выход (`POST /api/auth/logout`) очищает cookie в браузере. Сам сессионный
  токен stateless (срок годности плюс HMAC), серверного списка отзыва нет:
  скопированная до выхода cookie остаётся действующей до истечения срока.
- Честные границы: отдельного CSRF-токена нет — защита = `SameSite=Lax` +
  проверка `Origin`/`Referer` + CORS. Дефолтный `CORS_ORIGIN` доверяет
  локальному `localhost:5173` во всех режимах: принятый риск локального
  инструмента (follow-up — same-origin only в prod). Токен виден в адресной
  строке только до автообмена — и остаётся там при превышении лимита или при
  сетевом сбое, потому что токен ещё жив, а попытка должна оставаться
  повторяемой. Оболочка приложения не равна сессии — авторизацию подтверждает
  сервер. При 429 клиент делает не более двух автоповторов, дальше —
  статичная подсказка и кнопка «Обновить».

Вход закрывает все пути `/api` независимо от регистра. Сервер также отклоняет
запросы с чужим заголовком `Host` и изменяющие `/api`-запросы с чужим
`Origin`.

## Язык и тема

Интерфейс двуязычный (русский и английский) и переключается сразу; выбор
запоминается в браузере. Тема имеет режимы **light**, **dark** и **auto** и
запоминается так же.

## Где лежат данные

Всё хранится локально. База SQLite создаётся при первом запуске:

| Расположение | Как изменить |
| --- | --- |
| `~/.generaptor/generaptor.db` | по умолчанию |
| `--data-dir <path>` | флаг CLI (высший приоритет) |
| `GENERAPTOR_DATA_DIR` | переменная окружения |
| `DATABASE_URL` | полный URL базы (важнее каталога) |

Ни PostgreSQL, ни Redis, ни облачного хранилища. Чтобы сохранить статьи,
сделайте копию файла базы — и держите `provider-secrets.key` рядом с ним: без
этого файла сохранённые ключи провайдеров расшифровать нельзя.

Каталог данных создаётся с правами `0700`, файл базы и файлы обложек — `0600`
(на POSIX; на Windows это best effort, граница безопасности — NTFS ACL).
Обложки лежат в `<data-dir>/covers/` файлами `<articleId>-<n>.<ext>`; база
хранит только ссылку на файл. Если каталог данных расположен в общедоступном
месте, лаунчер печатает предупреждение о приватности.

### Удаление статьи

В **Истории** удалите статью через меню действий строки («…») → **Удалить**.
Появляется непрозрачный диалог подтверждения отдельным слоем: «Статья «{topic}»
будет удалена безвозвратно» с кнопкой **Удалить безвозвратно**. После
подтверждения статья удаляется из базы, **вместе с ней удаляются файлы её
обложек** из `<data-dir>/covers/`. Отмена закрывает диалог без изменений;
ошибка удаления показывается у действия, а не только в консоли.

## Переименованные настройки

Теперь все переменные окружения начинаются с `GENERAPTOR_`. Имена предыдущей
сборки больше не читаются — запасного варианта нет, поэтому старый `.env`
молча игнорируется:

| Настройка | Имя |
| --- | --- |
| Порт API | `GENERAPTOR_API_PORT` |
| UTM-метки в ссылках | `GENERAPTOR_UTM_ENABLED` |
| Cookie доступа | `generaptor_auth` |
| Реестр сайтов-источников | `GENERAPTOR_SOURCE_REGISTRY` |

После обновления переименуйте переменную порта в `.env` — иначе API вернётся
к `8787`, и выбранный порт будет проигнорирован.

## Сайты-источники

В сборке GeneRaptor **нет зарегистрированных сайтов-источников**: этап
исследования обращается к открытому вебу, и всё найденное считается
вторичным источником. Свои сайты подключаются через
`GENERAPTOR_SOURCE_REGISTRY` — путь к JSON-файлу:

```json
{
  "sites": [
    {
      "id": "example",
      "name": "Example",
      "baseUrl": "https://example.com",
      "doctorsIndex": "https://example.com/doctors",
      "servicesIndex": "https://example.com/services"
    }
  ]
}
```

Файл читается один раз при старте. Отсутствующий или битый файл — это
предупреждение, а не падение: приложение продолжает работать только с вебом.

`doctorsIndex` и `servicesIndex` — это имена полей, которые принимает разбор
реестра; они оставлены как легаси ради совместимости и указывают на ваши
собственные страницы, чем бы они ни описывались.

## Решение проблем

| Симптом | Что делать |
| --- | --- |
| `Prisma client is not ready` | Выполните `npx prisma generate` в папке установки — обычно это делает `npm install` |
| Порт занят | Запустите с `--port <другой-порт>` |
| Стартовая ссылка устарела / токен не принимается | Одноразовый токен уже потрачен автообменом, либо истекло окно 15 минут, либо сервер перезапущен — перезапустите студию: она откроет новую вкладку с новым токеном. В старой вкладке нажмите **Обновить** |
| Браузер не открылся | Автооткрытие — best-effort (и пропускается в CI / неинтерактивном терминале / с `--no-browser` или `--token`). Откройте URL из терминала и воспользуйтесь ссылкой «Ввести токен вручную» с токеном из баннера |
| Вкладку закрыли | Сессионная cookie принадлежит браузеру, а не вкладке: нажмите в старой вкладке **Обновить** — приложение подхватит сессию. Если вкладку закрыли до обмена, перезапустите студию: она откроет новую вкладку с новым токеном |
| Генерация сразу падает | Добавьте API-ключ в **Настройки → Провайдеры** и проверьте модель для каждого уровня |
| База со старой схемой | Удалите файл `.db` в каталоге данных: приложение пересоздаст базу через `prisma db push` при следующем старте |
| После `npx generaptor` ничего не видно | URL и токен остались в терминале — прокрутите консоль, из которой запускали, откройте URL и воспользуйтесь ручной ссылкой ввода токена |
| `EADDRINUSE` от API | В dev-режиме API слушает `8787`; остановите другой процесс или задайте `GENERAPTOR_API_PORT` — старое имя переменной порта больше не читается |

## Разработка

```bash
npm ci              # установка зависимостей
npm run dev         # dev-сервер Vite + API с горячей перезагрузкой
npm test            # юнит-тесты (vitest)
npm run test:e2e    # e2e-тесты (playwright, свой стек на SQLite)
npm run typecheck   # tsc --noEmit
npm run build       # typecheck + продакшн-сборка
npm run db:studio   # Prisma Studio на локальной базе
npm run lint:brand   # бренд-гейт: запрещённые токены в поставляемом наборе
```

CI (`.github/workflows/ci.yml`) выполняет те же шаги на Node.js 20 и 22, а
также аудит production-зависимостей (`npm audit --omit=dev --audit-level=high`):
он роняет сборку при advisory уровня high или выше.

e2e-набор поднимает собственный API и Vite-сервер на портах по умолчанию `8787`
и `5173`. Если эти порты заняты чем-то ещё, запустите его в изолированном режиме
на свободных:

```bash
GENERAPTOR_E2E_API_PORT=8899 GENERAPTOR_E2E_UI_PORT=5199 npm run test:e2e
```

Две переменные меняют **только тестовый стек** — это не продуктовые настройки, и
приложение их не читает. С явно заданным портом UI набор не переиспользует
сервер, который уже слушает на нём: этот сервер может принадлежать чужому
приложению.
